# Web application instructions

## Design references

- Before creating or changing a page or component, read `DESIGN.md` and open the relevant PNG references linked there. Reading the guide alone is not enough.
- Inspect both themes and the mobile, tablet, and desktop variants. For a new page without its own mockup, use the closest page and component patterns from those images.
- Follow the images for composition, spacing, controls, and responsive changes, except where a confirmed design exception in `DESIGN.md` applies. Preserve accessibility and confirmed product behavior; omit unsupported controls.
- When an explicit user requirement differs from the images, explain the difference and confirm that it is intended before making the affected change. Use confirmation already given in the conversation; do not ask again.
- Record each confirmed difference in the `Confirmed design exceptions` section of `DESIGN.md`. State the affected page or component, what the images show, and the behavior or design the user confirmed. Follow that exception during implementation and review; keep the images as the reference for everything else.
- Reuse the shared styles and components identified in `DESIGN.md`. Check the rendered result beside the selected images and name those references when explaining the UI change.
